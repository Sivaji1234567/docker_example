# Kubernetes Quick Revision Guide

## Why Kubernetes?

Docker can run containers on a single machine.

Problem:

* If the machine crashes, the application goes down.
* Scaling containers manually is difficult.
* Managing hundreds of containers becomes complex.

Kubernetes solves:

* Auto-healing
* Auto-scaling
* Load balancing
* Rolling deployments
* High availability

---

# Kubernetes Architecture

## Control Plane Components

### API Server

The entry point to Kubernetes.

When you run:

kubectl apply -f deployment.yaml

the request goes to the API Server.

Responsibilities:

* Receives all requests
* Validates requests
* Stores cluster state in etcd

---

### etcd

The database of Kubernetes.

Stores:

* Deployments
* Pods
* Services
* ConfigMaps
* Secrets
* Replica counts
* Entire cluster state

Think:

etcd = Brain Memory of Kubernetes

---

### Controller Manager

Responsible for maintaining the desired state.

Example:

Deployment:

replicas: 3

Current Pods:

2

Controller Manager notices:

Desired = 3
Current = 2

Creates one more Pod.

Think:

Controller Manager = "Make reality match the configuration"

---

### Scheduler

Assigns Pods to Nodes.

Example:

Node-1:
CPU 80%
Memory 70%

Node-2:
CPU 10%
Memory 20%

Scheduler places the Pod on Node-2.

If no Node has sufficient resources:

Pod Status = Pending

Think:

Scheduler = "Choose the best machine"

---

# Worker Node Components

## Kubelet

Agent running on every Node.

Responsibilities:

* Receives Pod assignments
* Starts containers
* Monitors containers
* Reports status back to API Server

Think:

Kubelet = Worker of the Node

---

## Container Runtime

Runs containers.

Examples:

* containerd
* Docker
* CRI-O

Responsibilities:

* Pull images
* Start containers
* Stop containers

---

# Core Kubernetes Objects

## Pod

Smallest deployable unit.

A Pod contains:

* One or more containers
* Shared network
* Shared storage

Example:

FastAPI Container

inside

FastAPI Pod

---

## Deployment

Manages Pods.

Features:

* Scaling
* Self-healing
* Rolling updates

Example:

replicas: 3

Deployment ensures 3 Pods always exist.

---

## Service

Provides a stable endpoint for Pods.

Problem:

Pods get new IPs after recreation.

Solution:

Service provides a fixed address.

Example:

fastapi-service

Traffic:

User
↓
Service
↓
Pods

Service also load balances requests.

---

# Self Healing

Delete a Pod:

kubectl delete pod pod-name

Result:

Controller Manager notices:

Desired = 3
Current = 2

Creates a new Pod automatically.

---

# Scaling

Scale Pods:

kubectl scale deployment fastapi --replicas=8

Result:

Kubernetes creates 8 Pods.

# ConfigMap

Stores non-sensitive configuration.

Examples:

* APP_NAME
* APP_ENV
* URLs
* Feature flags

Example:

APP_NAME=FastAPI Demo
APP_ENV=production

Benefits:

* Change configuration without rebuilding images
* Separate config from code

---

# Secret

Stores sensitive information.

Examples:

* Database Password
* API Keys
* JWT Secret
* AWS Credentials

Never hardcode secrets in code.

---

# Volumes

Provide persistent storage.

Without Volume:

Pod Deleted
↓
Data Lost

With Volume:

Pod Deleted
↓
Data Preserved

In production:

Usually databases are external:

* AWS RDS
* Azure SQL
* PostgreSQL Managed Services

prod

Benefits:

# Ingress

Defines routing rules.

Example:

api.company.com
↓
fastapi-service

admin.company.com
↓
admin-service

Think:

Ingress = Notice Board containing routing instructions

---

# Ingress Controller

Software that reads Ingress rules and performs routing.

Examples:

* NGINX Ingress Controller
* Traefik
* AWS Load Balancer Controller

Think:

Ingress = Rules

Ingress Controller = Executes the rules

Real-Life Example:

Notice Board:
Room 1 → Physics
Room 2 → Chemistry

This is Ingress.

Staff directing students to rooms.

This is Ingress Controller.
